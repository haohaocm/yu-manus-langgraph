# 计划：CA-6 HITL（写文件 / 危险命令人工确认）

> 状态：✅ **已完成**（2026-11-26；S0～S5；手工 `/stream` 已通过）  
> 术语：HITL（Human-in-the-Loop，人在回路）、interrupt（图中断）、diff（差异）、approve/reject（批准/拒绝）

### S0 拍板结论（2026-11-26，按建议）

1. 写文件（`write_file`/`str_replace`）一律 `need_approve`  
2. shell：黑名单 `hard_deny`，其余 `need_approve`  
3. 只读工具 `allow_auto`  
4. 挂闸方案 **A**（包装 + interrupt）  
5. 多 tool_calls **逐个**审批  
6. 拒绝 → 回喂模型继续  
7. HITL 依赖 checkpoint；提供 `HITL_ENABLED`  
8. 试玩页最小批准 UI（S4）  
9. 不做「总是允许」

---

## 1. 背景与目标

**要解决：** Agent 已能 `write_file` / `str_replace` / `run_shell`，但会**直接执行**。CA-6 在执行前插入人工闸：展示拟改内容（diff）或拟跑命令，人批准才执行；拒绝则把结果回喂模型，让其改方案。

**目标（MVP）：**

1. 对 **写文件类**工具：执行前生成 preview/diff → 挂起等确认 → 通过才真正写盘。  
2. 对 **shell**：黑名单硬拒 + 其余命令默认要批（可配置）。  
3. API / `/stream` 能下发「待审批」事件，并有批准/拒绝入口（试玩页最小 UI 即可）。  
4. 依赖已有 **checkpointer**（CA-4）：中断后状态可恢复。

**非目标：**

- 完整 IDE diff 面板（CA-8）  
- 「总是允许」策略商店、多用户权限  
- 用 LLM 单独判定危险（MVP 用规则）  
- plan 步骤整包审批（可后置）

---

## 2. 现状

| 能力 | 现状 |
|------|------|
| 写/改文件 | `fs_write` 直接落盘；有备份，无改前确认 |
| shell | `run_shell` 沙箱 cwd；无黑名单硬闸、无审批 |
| 图 | `reason ⇄ tools → summarize`；tools 内 `ToolNode` 一次跑完所有 tool_calls |
| 持久化 | Sqlite checkpointer + `thread_id` |
| 流式 | 节点事件 + summarize token；无 `pending_approval` 事件 |
| LangGraph | 已具备 `interrupt` / `Command`（可挂起与恢复） |

**关键设计抉择（S0 拍板）：**  
HITL 挂在哪？

- **方案 A（推荐 MVP）：** 在进入真正写盘/shell 前，用包装工具或 tools 前的「审批节点」调用 `interrupt(payload)`；恢复时用 `Command(resume=…)`。  
- **方案 B：** 拆 `tools` 为 `propose → wait_hitl → apply` 三节点。更清晰但改图更大。

计划默认走 **A**，若实现卡在 ToolNode 批量调用，再升为 B。

## 3. 步骤表

### S0 — 拍板策略与协议

| 项 | 内容 |
|----|------|
| **做什么** | 定：哪些工具要批、黑名单、SSE/API 事件形状、批准接口 |
| **工作目标** | 做完后团队对齐「什么要停、停的时候前端看到什么、点批准后图怎么继续」。**概念：** interrupt = 图执行暂停并吐出 payload；resume = 把人的决定塞回图。**协议建议：** 事件 `type=hitl_required`，字段含 `thread_id`、`action`（`write_file`/`str_replace`/`run_shell`）、`path`/`command`、`diff` 或 `preview`、`risk`（`write`/`shell`/`blocked`）。批准 API：`POST /agent/hitl/{thread_id}` body=`{decision:"approve"|"reject", note?}`。**边界：** 不做「总是允许」。**关系：** 后续步骤都按此契约。 |
| **如何测试** | 计划内贴 JSON 示例；你确认 S0 后再编码 |

### S1 — 规则引擎（危险判定 MVP）

| 项 | 内容 |
|----|------|
| **做什么** | 纯函数：`classify_tool_call(name, args) -> allow_auto | need_approve | hard_deny` |
| **工作目标** | 做完后不依赖 LLM 也能判定。**建议规则：** `write_file`/`str_replace` → 一律 `need_approve`；`run_shell`：匹配黑名单（如 `rm -rf`、`mkfs`、`shutdown`、重定向写 `/etc` 等简化列表）→ `hard_deny`；其余 shell → `need_approve`；只读工具（`read_file`/`grep`/`list_dir`/`semantic_search`）→ `allow_auto`。**I/O：** 输入 tool 名+参数；输出枚举+可选 reason。**边界：** 不解析所有 shell 语义。**关系：** S2 包装执行时调用。 |
| **如何测试** | `pytest`：若干命令/写文件用例断言分级 |

### S2 — 写文件 preview/diff + 包装执行

| 项 | 内容 |
|----|------|
| **做什么** | 批准前算 diff/新文件预览；批准后才调用现有 `write_text_safe` / `str_replace_safe` |
| **工作目标** | 做完后前端能看到「将改成什么样」而不是只看到工具名。**概念：** diff = 旧文本与新文本的行级差异（可用 difflib）。新文件则 preview 内容摘要。**边界：** 不做侧边 IDE。**关系：** 依赖 S1；挂到 S3 interrupt。 |
| **如何测试** | 单测：对已有文件 str_replace 产出含 `-old`/`+new` 的文本；新文件 preview 非空 |

### S3 — 图内 interrupt 挂起 / resume

| 项 | 内容 |
|----|------|
| **做什么** | 需审批的工具在执行前 `interrupt(...)`；`hard_deny` 直接返回 error 字符串给模型；提供 `resume_hitl(thread_id, decision)` |
| **工作目标** | 做完后：假模型触发 `write_file` 时图停住，不落盘；approve 后文件出现；reject 后模型收到拒绝信息并可再想。**依赖：** checkpointer 必须开。**边界：** 一次 tool_calls 里多个写操作 —— MVP 可逐个 interrupt，或打包成一次审批（S0 选定一种，推荐**逐个**更简单）。**关系：** 依赖 S0～S2；S4 接 SSE/API。 |
| **如何测试** | 假模型：跑到 hitl → 断言文件未写 → resume approve → 文件已写；另一案 reject → 无写盘且后续有 ToolMessage/错误回喂 |

### S4 — API + `/stream` 最小试玩

| 项 | 内容 |
|----|------|
| **做什么** | SSE 增加 `hitl_required`；页面展示 diff/命令 + 批准/拒绝按钮；调用 resume API 后继续收事件 |
| **工作目标** | 做完后你能在浏览器走通 Cursor 式「先看再准」。**边界：** UI 简陋即可。**关系：** 依赖 S3。 |
| **如何测试** | 手工：让 Agent 写 `outputs/hitl_demo.txt` → 页上出现待批 → 点批准 → 文件出现在 `artifacts/agent_workspace` |

## 5. 风险与回滚

| 风险 | 缓解 |
|------|------|
| ToolNode 一次多工具难逐个 interrupt | S0 选逐个包装；不行升方案 B |
| 无 checkpointer 时 interrupt 无法恢复 | HITL 强制要求 checkpoint；否则降级「直接拒写」或跳过 HITL 并打日志 |
| 试玩页 EventSource 中断后难 resume | 用 thread_id + 二次订阅/轮询；按钮调 POST resume |
| 回滚 | `HITL_ENABLED=false` 恢复旧直执行 |
