## 1. 背景与目标

把 Agent 结束从模糊的 `finished` / `error` 收成可区分终态，并统一走 Summarizer：

| 出口 | `status`（建议） | 触发 | 本阶段 |
|------|------------------|------|--------|
| 成功结束 | `completed` | `terminate(outcome=success)`；或 reason 无 tool_calls 的完整文本答复 | ✅ 实现 |
| 正常放弃 | `abandoned` | 模型显式 `terminate(outcome=abandon, reason=…)` | ✅ 实现 |
| 资源耗尽 | `budget_exceeded` | `step > max_steps`（token 硬上限后做） | ✅ 实现（仅步数） |
| 用户取消 | `cancelled` | 外部 cancel 信号 | ❌ 仅枚举/类型预留，不实现触发 |

**目标：** API/`run_manus` 返回可区分的 `status`（+ `end_reason`）；`answer` 按状态说人话；路由仍是 `→ summarize → END`。

**非目标（本计划不做）：**

- `cancelled` 的触发与 API 取消接口
- Token 硬上限打断（可只累加 `token_usage` 观测）
- 把「工具调用失败」自动映射成 `abandoned`（那是后续错误处理专题）
- Planner / Optimizer / SSE

## 2. 现状

- 图：`START → reason ⇄ tools → summarize → END`（`app/graph/build.py`）
- 结束信号：无 `tool_calls` → `finished`；`terminate` → `finished`；超步 → `error`
- 路由：`route_after_reason` / `route_after_tools` 看 `status in (finished, error)`
- 工具：`terminate(reason: str)`（`app/tools/local_tools.py`）
- 提示词：`NEXT_STEP_PROMPT` 仅提示用 `terminate` 停止；未区分成功/放弃

## 3. 实现思路（设计结论，供确认）

> 设计对照长文：[`../../knowledge/Agent结束策略-判定思路对照.md`](../../knowledge/Agent结束策略-判定思路对照.md)

**推荐：事件点写状态 + 纯函数统一裁决，而不是「每步后再挂一个独立结束阶段」。**

- 新增纯函数（例如 `app/graph/ending.py`）：
  - `apply_terminate_outcome(...)` / `mark_budget_exceeded(...)` / `mark_text_completed(...)`
  - `should_end(state) -> bool` 与 `route_after_*` 共用
  - 类型上预留 `cancelled`，提供 `mark_cancelled(...)` 可先空实现或仅单测占位
- **在自然事件发生处调用**（不要每个节点后强制 check）：
  - `tools`：若工具为 `terminate` → 按 outcome 调 ending
  - `reason`：无 `tool_calls` → `mark_text_completed`
  - `reason` 入口：`step > max_steps` → `mark_budget_exceeded`
- LangGraph 条件边只问 `should_end`；**不**新增 EndChecker 节点

对照长文：[`../../knowledge/Agent结束策略-判定思路对照.md`](../../knowledge/Agent结束策略-判定思路对照.md)

### 事件点 vs 工具错误（易混点）

```text
普通工具失败（参数/执行/内容） → ToolMessage(错误信息) → 回到 reason（未结束）
terminate(success)           → completed → summarize
terminate(abandon)           → abandoned → summarize
step > max_steps             → budget_exceeded → summarize
```

## 6. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 旧客户端只认 `finished`/`error` | API 可同时返回 `status` + `status_legacy`；或文档说明映射：`completed/abandoned`≈finished，`budget_exceeded`≈error |
| 模型不传 `outcome` | 默认 `success`；`reason` 含「无法/不能」等时可启发式 abandon（可选，默认不做启发式以免误判） |
| 无 tool_calls 一律 completed | 与「放弃应调 terminate」写进 prompt；单测用假模型覆盖 abandon 路径 |

回滚：恢复 status 枚举与 terminate 签名；删除 `ending.py` 引用。
