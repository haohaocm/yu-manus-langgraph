# CA 主线：目标与执行思路

> 总览（非单任务实现单）。CA-1 细节见 [`2026-11-24-CA-1-apply_patch写文件.md`](2026-11-24-CA-1-apply_patch写文件.md)。

---

## 1. 主目标

把「能读仓 + 能检索」升级成 **可改代码、可跑命令、可计划、可恢复、可观测、可人工闸** 的 Cursor 类 Agent 闭环。

| 层 | 能力 | 对应 |
|----|------|------|
| 行动 | 改文件、跑终端 | CA-1 → CA-2 |
| 编排 | 先计划再执行、失败回环 | CA-3 |
| 恢复 | 断点续跑 | CA-4 |
| 体验 | 流式事件（节点级）+ 正文 token | CA-5 → **SSE-TOK** |
| 安全 | 改前审批 / 危险命令 | CA-6 |
| 质量 | 固定题评测 | CA-7 |
| 壳 | Web/IDE（后置） | CA-8 |

**非目标（CA 阶段整体）：** 完整 IDE、向量库替换（VEC-DB）、完备投影（CTX-1）插队抢主线。

---

## 2. 执行思路（顺序与依赖）

```text
CA-1 写文件 ──► CA-2 终端 ──► CA-3 Plan 节点
                  │                │
                  └──── 可并行准备 ┘
         CA-4 Checkpointer（Plan/多步稳了再上）
         CA-5 SSE（可与 CA-4 穿插，偏体验）
         CA-6 HITL（写/跑已有后再加闸，避免空审批）
         CA-7 评测（至少 CA-1+2 可跑通再固化题集）
         CA-8 壳（不挡主线）
```

**原则：**

1. **先能改、再能跑、再编排** — 没有写/跑，Plan/HITL 没有抓手。  
2. **每项：计划 → 确认 → 小步编码 → 单测/手工 → 归档**。  
3. **安全渐进** — CA-1 用沙箱+备份；真正「人点确认」放到 CA-6。  
4. **索引不同步可接受** — 改文件后提示 `rebuild`，不在 CA-1 强绑重嵌。

## 3. 各任务一句话

| ID | 目标 | 思路要点 |
|----|------|----------|
| **CA-1** | 沙箱内写/改文本 | MVP：`write_file` + `str_replace`；备份；再考虑 unified patch |
| **CA-2** | 受控 shell | cwd=`WORKSPACE_ROOT`、超时、捕获 stdout/stderr/exit；黑名单可后加 |
| **CA-3** | Plan 节点 | LangGraph：规划 → 工具循环 → 可选「验失败再改」；假模型测图结构 |
| **CA-4** | Checkpointer | thread_id 续跑；持久化状态到本地 |
| **CA-5** | SSE（✅） | 按图节点推 reason/tools/summarize；`/stream` 试玩 |
| **SSE-TOK** | 正文流式 | **仅 summarize** 内 LLM token → 最终 answer 打字机；事件流仍整节点 |
| **CA-6** | HITL | 写文件/危险命令前返回 diff 等待确认 |
| **CA-7** | 评测集 | 小仓库固定题：改对文件？测试过？步数 |
| **CA-8** | 壳 | 对话 + diff 面板；可后置 |
