### 索引产物是什么（`artifacts/search_index/`）

阶段 B 建索引后，这里会放**可删可重建**的检索副产品（不是语料本身）：

| 产物 | 含义 |
|------|------|
| chunks 元数据 | 每个 chunk 的 `chunk_id` / `path` / `start_line` / `end_line` / `text`（或文本哈希） |
| BM25 侧 | 词表 / 文档频率等（或整包序列化的 ranker 状态） |
| Embedding 侧 | 向量矩阵 + 模型名/维度（阶段 B1） |
| 清单 manifest | 语料根、窗长、overlap、生成时间，便于判断是否过期 |

语料在 `artifacts/corpus/`；索引在 `artifacts/search_index/`（已 gitignore 内容，保留目录）。

## 阶段 A — Chunking（文本切块）✅

### 工作目标

把选定目录下的文本文件切成带定位信息的 **chunk（文本块）** 列表，为建索引做准备。

### 实现（已落地）

1. 配置：`search_corpus_dir=artifacts/corpus`，`search_chunk_lines=40`，`search_chunk_overlap=10`。  
2. 扫描 `*.py` / `*.md` / `*.txt`；跳过 `.venv` 等。  
3. 行滑动窗口：`app/search/chunking.py`（`split_line_windows` / `chunk_file` / `chunk_corpus`）。  
4. 每块：`chunk_id`、`path`、`start_line`、`end_line`、`text`。  
5. 单测：`tests/test_search_chunking.py`（8 passed）。

### 测试方法

| 用例 | 做法 | 期望 |
|------|------|------|
| A-T1 基本切块 | 临时目录放 `a.py` 80 行 | chunk 数 ≥ 2；行号连续、有 overlap |

| A-T3 空/跳过 | 空目录或仅二进制 | 不崩；返回 [] 或跳过 |

## 阶段 B — Index + Scoring + Retrieval（索引、打分、检索）

### 工作目标

对 chunk 建 **index（索引）**，给定自然语言 `query`，返回 top-k 命中（path、行号、score、摘录）。

### 实现思路（两条轨，确认选一）

**B0 — 词法（教学台阶）✅**

- 自写极简 Okapi BM25（`app/search/bm25.py`），无第三方。  
- `app/search/index.py`：`build` / `save` / `load` / `search_bm25`。  
- 落盘：`artifacts/search_index/chunks.json` + `manifest.json`（load 时重建 BM25）。  
- 单测：`tests/test_search_bm25.py`（7 passed）。

**B1 — Embedding（主路径）✅**

1. `app/search/embed.py`：`StubHasherEmbedder`（默认离线）+ `HttpOpenAIEmbedder`（`EMBEDDING_BACKEND=http` → `:18001`）。  
2. `app/search/embed_index.py`：建索 / 落盘 `chunks.json`+`vectors.json`+`manifest.json` / cosine 检索。  
3. 配置：`embedding_backend` / `embedding_base_url` / `embedding_model` 等。  
4. 单测：`tests/test_search_embedding.py`（默认 stub；打分明细用 `-s` 打印）。

### 测试方法

| 用例 | 做法 | 期望 |
|------|------|------|
| B-T1 建索引 | 对 A 的 fixture 建 index | 文件存在或内存 size = chunk 数 |
| B-T2 语义命中 | query 贴近某函数注释/docstring 的意思 | top-k 含目标 `path` |
| B-T3 top_k | `top_k=3` | 至多 3 条，按 score 降序 |
| B-T4 空 query | `""` | 明确 error 或空列表，不抛未捕获异常 |
| B-T5（B1）向量维 | 同模型 | 所有向量 dim 一致 |

**阶段完成标准：** 命令行或单测能跑通「一句中文/英文 query → 打出命中 path」。

### Hybrid（混合）✅

- `app/search/hybrid.py`：`hybrid = (1-α)·bm25_norm + α·emb_norm`（先按本次 query max 归一化）
- 配置：`HYBRID_ALPHA`（默认 0.5）
- 单测：`tests/test_search_hybrid.py`；语料增补 `agent_tools_guide.md` / `hybrid_ranking_lab.py` / `kitchen_decoy.md`

## 阶段 C — Tool：`semantic_search`（查询入口）

### 工作目标

把 retrieval 暴露为 Agent 可调用的 tool（工具），与 `grep`/`read_file` 并列。

### 实现思路

1. `@tool semantic_search(query: str, top_k: int = 5) -> str`  
2. 内部：确保 index 已加载（无则对 corpus 懒建一次）。  
3. 返回人类可读短文，例如：

```text
semantic_search hits=3 query="..."
1. score=0.82 path=app/tools/path_sandbox.py:12-40
   preview: ...
2. ...
hint: use read_file on path for full content
```

4. 结果过长走 CE-3 `maybe_persist_tool_result`（经 loader 包装即可）。  
5. `load_agent_tools`：**本地始终挂上**（mcp 开关无关）。  
6. 提示：index 失效时允许 `rebuild` 参数或独立脚本 `scripts/build_search_index.py`。

### 测试方法

| 用例 | 做法 | 期望 |
|------|------|------|
| C-T1 invoke | `semantic_search.invoke({"query":"..."})` | 含 `path=` 与 `score` |
| C-T2 loader | `load_agent_tools` 名称集合 | 含 `semantic_search` |
| C-T3 与沙箱 | 返回 path 均在 workspace 内 | 无 `../` 逃逸 |
| C-T4 无命中 | 乱码 query | 友好「no hits」，非 traceback |

**阶段完成标准：** 不跑图也能用工具查到 CE-2 相关文件（如 path_sandbox）。
