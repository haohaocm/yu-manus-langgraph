# 开发习惯与长期提示（持续提炼）

**最后更新：** 2026-11-26

## 学习与节奏

1. **按步推进**：一次只做一个子步骤（如 CE-2.1 → 2.2），不要一次甩整阶段全部计划/实现。  
2. **先对齐理解再动手**：先确认「对不对 / 大厂怎么做」，再编码。  
3. **先计划后编码**：开发计划含步骤、目标、如何测试；明确确认后再改代码。  
3b. **工作目标写给读者看**：每步目标用白话写清「做成啥、概念、I/O、边界、与前后步关系」，宁可多几行，禁止只有文件名（见 `dev-plan-format` 规则）。  
4. **学生视角文档**：拆解文要写「学什么 / 完成标准」，避免只有工程黑话。  
4b. **优先级 ≠ 立刻执行**：「高优」= 记入后备清单；做完当前主线后再从高/中/主线里挑选。完备投影等大模块可等 Agent 主流程更完整再上。  
4c. **成熟投影可后置**：近窗最小版够用时，CTX-1 不必插在检索/编辑/终端之前。

## 工程偏好

5. **配置进 Settings/.env**：阈值、路径等可调，少写死。  
6. **能延后的复杂性先砍**：如自动删文件、分片、摘要模型、向量库——先最小闭环。  
7. **本机落盘、远程只取数**：工具长结果在本机写文件，不交给远程写盘。  
8. **测试要可复跑**：假模型/单测优先；真模型/隧道作为补测。  
8b. **embedding 无 stub**：检索/EMB 相关测前必须开 `18001→bge`；连不上就 fail，不静默降级。  
8c. **启项目双服务**：真联调 = Qwen(`18000`) + bge(`18001`)；见 `项目启动清单.md`。  
8d. **改实验室 GPU/模型前先停本机应用**：避免隧道半截请求干扰对比；改完再启。  
8e. **测前先检环境**：真模型/SSE/联调前跑 `.\scripts\ensure_env.ps1`（缺则 `-StartMissing`）；已占用端口不杀不重启。实验室脚本：`scripts/check_lab_services.sh`。  
8f. **测后关环境**：本轮联调结束跑 `.\scripts\stop_env.ps1`（实验室 `stop_lab_services.sh`）；用户说继续测则跳过。  
8g. **流式分工**：事件流=整节点；最终 answer 打字机=优先只做 summarize token（SSE-TOK）；reason token 后置。  
8h. **默认可写区**：`WORKSPACE_ROOT=artifacts/agent_workspace`，勿默认仓库根；改工程则改该配置。试玩续聊要带 `thread_id`。  
9. **文档省 token**：日常只维护瘦「待办」；已完成进「归档」，默认不整份加载。

## 沟通偏好

10. 用表格/对照把「理解 vs 纠正」说清。  
11. 回答先给结论，再补细节；少空话。  
12. Win11 环境：跨平台实现优先（如纯 Python grep），少绑 Linux 专用命令。  
13. 术语：常用 English 专名保留英文 + 括号中文（见规则 `bilingual-terms`），勿生硬全译。  
14. **跑测结果进对话**：执行 pytest / 脚本验收后，把命令与关键输出贴进回复；检索类步骤还要贴 **打分/命中明细**（score、path、行号），不要只写 PASSED。  
15. **方案评审**：用户提出方案时，Agent 须以优秀工程师视角评价（优点 / 风险 / 更优做法），再落地；不要只附和。  
16. **中文注释便于学习**：新增/改动的业务代码写清楚中文注释（模块头、关键函数、非显而易见分支）；术语仍保留 English（中文）；勿刷屏式逐行翻译。  
16b. **函数必写功能说明**：每个新增/改动的函数至少一句 docstring（做什么）；见规则 `function-comments`。
